# Decisions

One line each. The reasoning lived in the design conversation, not here — a long
rationale file is the first thing to go stale and the last thing anyone reads.

**How to reverse** is the column that matters. If a decision does not fit your project,
change it deliberately rather than working around it.

## Deliberately deferred

C++ / GDExtension. ECS. Game capture and vision loop. Golden-frame diffing. Editor
introspection plugin. Multi-process netcode harness. CI. Export presets.

Each is a real capability with a real cost. None is needed before the first feature
ships, and adding them up front means maintaining tooling for code that does not exist.

## Revision history

**Revision A — the gate must not pin what it cannot produce.** Shipping
`src/tools/validate_resources.gd` hash-pinned while its canonical formatting is decided by
`gdformat` created an unpassable gate: the file failed `format`, and the agent was
forbidden from touching it. The rule now is that no file is hash-pinned if its canonical
form is defined by a tool the author cannot run. `.gate.sha256` is generated locally
after formatting, never shipped.

**Revision B — density.** `AGENTS.md` was 306 lines and got read in three chunks, with
five of the first six tool calls spent on documentation. Detail moved to `docs/RULES.md`
and `docs/GATE.md`; the contract is now a single read with the bootstrap rule first.

**Revision C — the gate was hiding the diagnosis.** Godot emits every parse error as two
lines, the message then `at: ... (res://file.gd:42)`. The scanner kept only lines matching
the error regex, so the second line was discarded on every error. Across a 242-turn field
session: 57 errors shown, zero line numbers, and the same files re-read hundreds of times
because there was no other way to locate a fault. Errors are now grouped by signature with
every location preserved. The generalisable rule: whenever the gate filters engine output,
test what it drops, not only what it keeps.

**Revision D — teach the invariant, not the error.** A field session lost 19M tokens to a
non-converging loop: the agent threaded a raw parsed `Dictionary` into a compositor, then
tried to fix every downstream use site. GDScript has no safe cast from `Variant`, so each
fix revealed the next. The wrong response is a helper library (`as_int`, `as_color`, then
`as_vector2i` forever); the right one is a single directional invariant, enforced by the
new `types` stage: convert external data once in `src/scripts/data/`, pass only typed values
into `src/scripts/logic/`. Same revision fixed three structural faults that compounded the
loop: `-d` puts Godot in the interactive debugger, so a parse error broke, prompted, read
an inherited stdin, resumed and spun — 3 million lines and a 165 MB log. stdin is now
closed, logs capped at 2 MB keeping the tail, and stages that load GDScript are skipped
when parsing is broken. `arch.rules.json` was unpinned because adding a module is a
legitimate change that pinning made impossible to make honestly, and `config/name` was
still `"Coop"` from an earlier working title, which told every agent it was building
something else.

## Revision E — knowledge as retrievable skills

Three sessions showed the same pattern: reference documentation existed, was pointed at
from `AGENTS.md`, and was never opened. `docs/GDSCRIPT.md` went unread through 105 parse
errors while the agent guessed; `src/scripts/data/level_format.gd` contained the exact
Variant-boundary answer and was never looked at. Organisation was not the problem —
retrieval was. Skill files have an advertisement layer: only `name` and `description`
load at startup, so an agent can see that knowledge exists without paying for it, and
pull in the body when it decides it is relevant. `.agents/skills/` is the location most
agent runtimes read.

Two mechanisms make that actually fire. Descriptions are written as triggers ("use when
you are about to ...") rather than topics, because matching a topic requires already
knowing what is inside it. And every failing stage that maps to a skill prints a pointer
to it, because a pointer at the moment of failure lands where attention already is,
while a pointer in a file read once at session start competes with everything since.

The hard rule on content: a skill may contain concepts and decision rules, and may not
contain a fact the code can contradict. No stage counts, no timeouts, no constants, no
file paths into gate internals. The moment a skill states a number it becomes a second
source of truth and is wrong within a revision. Facts stay generated.

API truth moved off the web and onto the engine binary. `--doctool` dumps the class
reference for exactly the installed version, offline, so a lookup cannot drift from what
will run. Web documentation remains right for conceptual material, which the dump does
not carry. A `skills` gate stage exists because a skill whose frontmatter name does not
match its folder is silently ignored — no error, the knowledge just never loads, which
is the worst possible failure mode for something whose entire purpose is being found.

The decision log records any choice that would make a later agent act differently, not
only technical ones. Art direction, scope, audience, monetisation and moderation all
change downstream answers and none is recoverable from code. There is deliberately no
category taxonomy and no list of expected decisions: both would drift, and both would
quietly exclude games unlike the ones the kit was written against. Entries are raised by
whichever skill hits a fork it cannot resolve, rather than by a fixed questionnaire, which
is what prevented an honest "not decided yet" from being converted into a fabricated value
under gate pressure.


Design is written before the code that delivers it, not summarised after. The earlier rule
said a document lands in `docs/design/` once it is settled enough that code depends on it,
which positioned design as a conclusion drawn from implementation and produced an empty
folder across eight slices. A section is now created as soon as there is a real question
and states its own resolution, so a reader can tell a leaning from a commitment. The
constraint that replaces it is tier gating: a section may exist without an answer, and may
never be filled past the resolution actually reached, because a plausible inference written
into a gap reads as intent and gets built on.

Discovery is a separate pipeline from delivery, triggered by the human describing an idea
or by an agent unable to say why a piece of work exists. Graduation-from-implementation
alone is a trickle, which is the mechanical reason design stayed empty. A slice cites the
section establishing the end state it serves rather than the feature immediately above it:
"so the world is visible" constrains nothing, while "content must be composable from parts
small enough to author, validate and moderate, and small enough to cross a peer-to-peer
wire" names the pressures that decide the answer. If the nearest citable thing is one link
up from the work itself, that is the signal to enter discovery rather than write a shallow
rationale.

`revisit_if` is required on every decision entry. Recording what was decided and why leaves
no way to tell a provisional choice from a load-bearing one, so six months on every entry
reads as permanent. `"permanent"` is a valid answer and is suppressed in the plan view,
because showing it on every card would erase the distinction the field exists to draw.

The `action` field on a proposed file is validated against `git ls-tree` at `baseline_sha`.
It was rendered but never checked, so `create` on a file that already existed reached a
human twice. The mistake matters beyond bookkeeping: it is the moment extend-before-create
gets skipped, and it precedes writing a second copy of something beside the original.

A slice cites the design it descends from in `proposal.json` `design_refs`, rendered above
the structure in the plan as *Why this work exists*. A dangling reference fails the gate; an
absent one only warns. Failing on absence would produce fabricated ancestry, which is the
failure we have already watched twice — a rule satisfiable only by writing something gets
satisfied by writing something false. The reference must reach an end state rather than the
feature above it: "the world must be visible" rules nothing out, "content must be composable
from a vocabulary a player can author and a peer can validate" tells you what to build.

Design is written before the code that delivers it, at whatever resolution it has. The
previous model — a section lands once it is settled enough that code depends on it — made
design a summary of what was built, and produced an empty `docs/design/` across eight
slices. A section may now be an open question, provided it says so and is not filled past
what was decided.

`tools/friction.py` reports authoring churn from committed history, at slice boundaries,
never in the gate. An agent experiences a tedious task and a quick one identically, so the
signal that a tool is missing has to be surfaced deliberately. It under-reports by
construction: repeated attempts inside one turn leave no trace, which is why the skill asks
the agent to notice those itself.

## Artefact keys are validated, not described

`proposal.json` shipped as empty arrays with the item shape documented only in prose. An
agent filling it invented reasonable key names — `change` for `action`, `why` for `purpose`,
`responsibility` for `role` — and every reader silently dropped what it did not recognise.
Five files each carried a written justification and the plan rendered none of them. The
`action` field was absent entirely, so the conformance check that validates it never ran
once. One undocumented schema, four separate visible symptoms.

`tools/schema.py` is now the single source of truth for artefact fields, and the `schema`
stage blocks on an unknown key while naming the intended one. A bare rejection would leave
the agent guessing a second time.

Two fields in the spec were adopted from what the agent invented rather than rejected:
`boundary_data` on a module states what crosses the type boundary, and `not_yet` on a
direction entry stops an accommodation quietly becoming an implementation. Both are better
than anything specified for them.

The templates now document their own shape inline using `_`-prefixed keys. Every reader
strips them, so an example cannot be mistaken for proposed structure — without that, a
fresh clone reads as a project with three modules already planned.

## Bootstrap never blocks on a file another tool owns

`editor-settings` reported `MISSING` on every run, because Godot rewrites that file on exit
and discards the patch. `complete` was therefore permanently `false`, and `AGENTS.md`
instructs an agent to run `--fix` whenever it is. One session ran bootstrap 25 times, 12 of
them with `--fix`, achieving nothing each time.

Checks may now be advisory: reported, never counted toward completion. This restores a rule
written in the first revision and then broken — never gate on a file whose canonical form is
controlled by a tool the gate cannot drive.

## Approval accumulates across slices

The hierarchy diagram compared code against the current proposal only, so every function
approved in slices 0 to 2 rendered red as *exists without approval*. A reviewer reading it
concluded the agent had built unapproved work. A diagram that cries wolf is worse than one
showing no state at all, because it trains the reader to ignore the colour.

Approval is now read from every proposal in git history whose `status` reached `approved`. A
draft that was never signed off is not evidence of approval. Files approved earlier render
as `existing` rather than `unproposed`, which distinguishes legitimate pre-existing code
from something that appeared without consent.

## Every layer states why, not just what

File rows rendered as `to do | proposal.json` and nothing more. Module rows showed a role
but no reason. Only functions carried an explanation, which is the wrong way round: the
coarser the layer, the less recoverable a missing reason is, because you cannot infer why a
file is being touched from its path.

`why` is now required at module, file and function level, and rendered at each. A row with
no reason shows *no reason given*, so an incomplete proposal is visibly incomplete rather
than looking like a rendering fault. `considered_existing` moved above the hierarchy
diagram, because extend-before-create is the decision a reviewer most needs to check and it
was easy to miss below a large graph.

## Open questions age visibly

`questions[]` rendered as a flat list, so a question raised six weeks ago looked identical
to one raised yesterday. Unanswered questions do not stay neutral: they get resolved by
default, silently, by whoever next writes code in that area.

The shape stage now prints each question's age and flags anything unanswered for 14 days or
more. It reports rather than fails. A consciously parked question is not a defect, and
blocking would train the human to delete questions instead of answering them.

## The evidence pack is the deliverable; the model is an adapter

A retrospective needs to reconstruct what happened during a slice. The obvious shape is
an agent that investigates. The shape chosen instead is a deterministic evidence pack
built from session logs, git, the artefacts and the gate logs, with a model reading it.

Two reasons. Every third-party integration attempted in this kit has been a dead end
when it was load-bearing, so an adapter that can be swapped costs nothing while a
dependency costs a revision. And a pack works with any agent, or with none: it can be
handed to a chat window, a CLI, or read by a human.

`--print` therefore has no dependencies at all. `--sdk` exists for one property the CLI
cannot provide: thread resumption, so a retro can be reopened and probed further within
the same slice instead of starting cold.

Reverse by: deleting `tools/retro_sdk.py`. `--print` is unaffected.

## Regex friction classification was tried and abandoned

The first version classified human messages as friction with a pattern list: "not what I
asked", "why did you", "revert". Tested against a real session it caught **zero of four**
genuine friction messages.

The reason is that real friction reads as observation, not accusation. "Built now shows
to do not written" is a defect report with no complaint word in it. "I'm seeing a lot of
unproposed functions here" is a defect report phrased as an observation.

So the pack extracts every human message verbatim and the model classifies. The regex
survives as a low-recall hint for the terminal summary, with the prompt explicitly
telling the model that an empty hints array is meaningless.

Reverse by: nothing depends on the hints.

## A retro may not act on its own conclusions

A retro that can edit rules, skills or gate files closes the loop without a human. It
also accretes plausible-sounding rules that nobody agreed to, and the kit degrades
without anyone noticing. Every rule in this kit that was added under pressure to satisfy
a gate produced a workaround rather than compliance.

Findings and proposed goals go to `docs/retro/`. The SDK adapter denies write tools. The
human promotes what they agree with.

Reverse by: removing the deny list from `tools/retro_sdk.py` and the rule from
`AGENTS.md`. Not advised.

## The gate nudges; it never spends quota

An automatic retro is genuinely useful and a runaway loop has already happened once in
this kit: `editor-settings` could never pass, so an agent ran `bootstrap.py --fix` twelve
times in one session.

So the gate prints one line when a retro is warranted and calls no model. Triggering is
opt-in via `--if-warranted`, and a per-slice lock file means a trigger firing twice
cannot spend twice.

Reverse by: deleting `retro_nudge()` from `check.py`.
